# 日程同步与一致性校验

客户端版本：3.0.8。新增服务接口：`GET /api/v1/sync/snapshot`，需要用户登录。

正常同步按记录 UUID、版本和操作 UUID 交换变化。单次同步执行：首次完整校准（仅升级后的第一次）、增量拉取、分批推送、再次增量拉取、完整快照核验。手动同步和后台同步共享一个执行中的 Promise；上传期间新的编辑保留在队列中，并以服务器确认版本为新的 baseVersion。

推送响应的 cursor 不能作为客户端已读游标。客户端只在下载记录成功落盘后确认读取进度。快照接口通过单条 PostgreSQL 查询返回同一 MVCC 快照下的记录和账号游标，用于发现旧客户端曾经跳过的记录。

首次校准保存 `events.sync-repair-*.json` 备份。云端独有记录导入；本地未上传记录入队；干净的旧版本采用云端新版本；同版本内容不同、双方修改、已同步记录在云端消失等情况保留本地并进入冲突。删除标记参与核验；云端已有删除记录不会被本地旧记录自动复活。

客户端对快照内容和本地落盘内容使用相同的规范化规则与 SHA-256。日程内容、UUID、版本和删除状态参与校验；本地数字 ID、createdAt、updatedAt 和内部同步字段不参与业务内容哈希。只有哈希相同、无待上传记录、无冲突时返回同步成功，并记录 verifiedAt、verifiedCursor 和 verifiedHash。不同设备在相同 verifiedCursor 上拥有相同 verifiedHash，表示其同步业务内容一致。

目前使用完整快照进行最终核验，因此核验下载量与账号记录总量成正比；上传和常规拉取仍是增量。适合当前个人日程规模。大规模账号可进一步增加分页快照或服务端摘要协议，但必须保留同一快照的版本边界。

联网后的最终一致取决于所有设备升级至 3.0.8、使用相同服务器和账号、完成同步并处理冲突。离线、正在编辑或其他设备仍使用旧版时，不保证即时一致。
